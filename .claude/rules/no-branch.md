# ブランチを分けずに main へ直接コミットする

## 概要

体験版をリリースするまで、このプロジェクトでは feature ブランチを作らない。作業はリポジトリ直下の `main` で行い、コミットも push も `main` に直接する。`creating-commit` / `closing-task` など、ブランチや PR を作る skill を使うときも、ブランチ作成と PR 作成は飛ばす。

## 理由

個人開発で、レビュー相手がいない。ブランチを切ると、Godot エディタで開いている直下のチェックアウトと `main` がずれる。そのうえ毎回マージと削除の手間がかかる。

**Why:** ユーザーから「このプロジェクトではブランチ分けなくていいや。体験版リリースとかしたら」と指示があったため（2026-11-27、NA-100 の後）。

## 適用

- コミットは `main` にそのまま作る。メッセージは `NA-XX: ...` の形式のまま。
- push は `git push origin main`。push するのは、ユーザーに頼まれたときだけ。
- 体験版のリリース後は、ブランチ運用を始めるかどうかをユーザーに確認する。
